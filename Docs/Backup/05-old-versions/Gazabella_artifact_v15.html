ما هي Gazabella؟

Gazabella ليست متجراً يملك مخزوناً — بل هي وسيط ذكي (Aggregator Marketplace) تعمل كحلقة وصل بين 3 متاجر شريكة أو أكثر وعملاء غزة. العميل يتسوق من واجهة واحدة موحّدة، لكن المنتجات تأتي من متاجر متعددة ويصله توصيل واحد منسق.

🎯 المشكلة

التسوق من متاجر كوزمتيكس غزة متفرق — منتجات في متجر، سعر أفضل في آخر، بدون تجربة توصيل موحدة.

💡 الحل

واجهة واحدة للتصفح والشراء، طلب واحد من متاجر متعددة، فاتورة واحدة، توصيل واحد.

💎 المميز

المنتجات تظهر تحت علامة Gazabella فقط — المتاجر الشريكة لا تُذكر للعميل. تجربة مصمّمة للسياق الفلسطيني.

💡
الموديل الاقتصادي: Gazabella تأخذ عمولة من كل طلب. المتجر الشريك يضع سعر الجملة، Gazabella تضيف هامشها وتبيع بسعر التجزئة للعميل. التسوية تتم شهرياً.

🔀 Master Order

طلب رئيسي واحد يحتوي على Sub-Orders بعدد المتاجر. العميل يدفع مرة واحدة، الـ Master Order يوزع على المتاجر تلقائياً.

📋 Sub-Order

كل متجر يرى vendor_order الخاص به فقط. يغير حالته من "قيد التجهيز" → "جاهز للتوصيل" بدون رؤية معلومات المتاجر الأخرى.

🚚 التوصيل الموحد

حتى لو جاءت المنتجات من 3 متاجر — عملية توصيل واحدة للعميل. التنسيق داخلياً بين المتاجر ومزود التوصيل.

💳 الدفع — Jawwal Pay

بوابة الدفع الوحيدة في MVP — دفع إلكتروني نظيف

💡
لماذا Jawwal Pay أولاً؟ الأكثر انتشاراً في فلسطين، بدون حاجة لبطاقة بنكية، يدعم OTP للتأكيد، يعمل حتى في ظروف القطاع البنكي الصعبة.

خطوات تكامل Jawwal Pay

1
Backend: POST /orders → ينشئ الطلب في DB
2
Backend: يطلب Payment Intent من Jawwal Pay API
3
Backend: يُرجع payment_url للـ Frontend
4
Frontend: يعيد توجيه العميل لصفحة Jawwal Pay
5
Jawwal Pay: يُرسل Webhook إلى /webhooks/jawwal-pay
6
Backend: يعالج Webhook → يؤكد الطلب → يرسل إشعاراً

بوابات مستقبلية (بعد MVP)

بنك فلسطين · Pal Pay · Mal Chat — كل بوابة تُضاف عبر Interface موحد بعد تقييم الطلب الفعلي من السوق.

نموذج ربحية الطلب

معادلة الإيراد (نموذج العمولة)

إيراد المنصة = سعر البيع × نسبة العمولة
مستحق المورد = سعر البيع × (1 - نسبة العمولة)
هامش المساهمة = إيراد المنصة - رسوم الدفع - رسوم التجميع - التغليف

مثال افتراضي معلن — ليس توقعاً سوقياً

قيمة الطلب: 150 ₪ (3 أصناف، مورد واحد)
عمولة المنصة (15%): 22.5 ₪
مستحق المورد: 127.5 ₪
رسوم Jawwal Pay (2%)*: 3 ₪
رسوم التوصيل (ثابتة)*: 10 ₪ (يدفعها العميل)
هامش المساهمة: 22.5 - 3 = 19.5 ₪

⏱ عقد الحجز — القواعد النهائية (رد على Codex)

✅ Codex محق: الـ ping لا يجب أن يمدد الحجز تلقائياً — الزيارة المستمرة للسلة لا تعني نية الشراء.
القاعدة التفصيل
بداية الحجز عند الإضافة للسلة → expires_at = now() + 15 min
الـ heartbeat لا يمدد الحجز — يقرأ الحالة فقط ويعيد expires_at الحالي
تمديد الحجز يحدث فقط عند انتقال المستخدم لصفحة Checkout فعلياً
POST /orders/checkout/begin → يجدد الـ TTL إلى now() + 15 min
الحد الأقصى للتمديد تمديد واحد فقط — الحجز لا يتجاوز 30 دقيقة إجمالاً من أول إضافة
response الـ heartbeat {"reservations": [{"variant_id": 107, "expires_at": "...", "qty": 2}]}
انتهاء الحجز الخادم هو المرجع — عند وصول العداد للصفر، Codex يستعلم الخادم ويوقف متابعة الشراء
إضافة endpoint جديد: POST /orders/checkout/begin — يُمدد الحجز ويعيد server_now + expires_at لكل عنصر. يُستدعى مرة واحدة عند الانتقال لصفحة الـ Checkout.

تكامل Jawwal Pay

بوابة الدفع الفلسطينية الوحيدة المتاحة في غزة — تدفق 6 خطوات بالكامل عبر Webhook.

1
Initiate
POST /payments/init → إرسال المبلغ + reference → Jawwal يُعيد payment_url
↓
2
Redirect
العميل يُعاد توجيهه إلى صفحة Jawwal Pay ليدفع بمحفظته
↓
3
Webhook Received
Jawwal يُرسل callback POST /payments/webhook مع status + ref
↓
4
Verify Signature
التحقق من HMAC signature لضمان صحة الـ Webhook قبل المعالجة
↓
5
Update & Split
تحديث حالة الـ Master Order → تشغيل SplitOrderJob → إنشاء vendor_orders
↓
6
Notify All
إشعار العميل + كل متجر معني + بثّ WebSocket + SMS تأكيد

١٤. ملاحظات هامة للـ Codex / Intergravity

  • لا تعدّل openapi.yaml إلا بعد موافقة أشرف — هو المرجع الملزم
  • store_id و commission_amount محظوران نهائياً في أي Response للعميل
  • vendor_orders داخلية فقط — العميل يرى order الرئيسي فقط
  • Heartbeat READ-ONLY — أي محاولة للتمديد فيه تكسر قاعدة الأمان
  • OTP test_code في .env للتطوير فقط — لا تضعه في production
  • is_extended ليس حقلاً في DB — يُشتق دائماً من extended_at !== null
  • دائماً 127.0.0.1 وليس localhost في جميع الإعدادات
  • Bearer Token فقط للـ APIs — لا SPA cookies، لا CSRF middleware على API routes
  • Order ID في الـ URL هو order_number (مثل GAZ-2026-0001) وليس الـ numeric id
  • نطاق المدن محصور في config('gazabella.active_cities') — لا تضع قيم مباشرة في الكود
  • expires_at هو الاسم الوحيد لوقت انتهاء الحجز في جميع الـ API responses — لا reserved_until
