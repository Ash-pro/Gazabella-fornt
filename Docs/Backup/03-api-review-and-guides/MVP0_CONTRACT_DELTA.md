# ملحق عقد MVP0 المحلي — 26 سبتمبر 2026

هذا الملحق يصف نسخة Backend المحلية المعدلة، ولا يدّعي أن الخادم المنشور يدعمها. ملف OpenAPI الأصلي لم يُعدّل. جذر المسارات `/api/v1`.

## الهوية والسلة

- `POST /auth/guest/init`: هوية ضيف تُرسل لاحقًا في `X-Guest-UUID`.
- `POST /auth/otp/verify`: الحقول `phone` بصيغة `+970...` و`otp`، و`name` اختياري. يعيد `token` و`user` مباشرة، ويدمج سلة الضيف ذريًا.
- `GET /auth/me`: المستخدم المصادق عليه فقط، دون الحقول الداخلية.
- `POST /cart`: `product_variant_id` و`quantity`، لا `product_id`. الحد التراكمي لكل خيار 10 أو المتاح، أيهما أقل.
- استجابة عنصر السلة تشمل `product_id`, `product_slug`, `variant_id`, `stock` وحالة الحجز. تعديل الكمية يلغي الحجز السابق ويلزم حجز جديد.
- `POST /cart/reserve`: حجز المخزون، ويعيد `expires_at`.

## مراجعة الطلب وإنشاؤه

1. تسجيل الدخول، ثم حجز السلة.
2. `POST /orders/checkout/begin`: تمديد واحد للحجز، وإرجاع `expires_at`, `seconds_remaining`, `delivery_options`, `active_cities`.
3. `POST /orders/checkout/quote`: جسم `{delivery_option_id, city, coupon_code?}`. يعيد رمز عرض `quote_token` والإجماليات والعملة ILS والصلاحية. صلاحيته لا تتجاوز خمس دقائق أو نهاية الحجز.
4. `POST /orders` بهيدر `Idempotency-Key` قيمته UUID ثابت للمحاولة. الجسم:

```json
{
  "delivery_option_id": 1,
  "payment_method": "cod",
  "quote_token": "<token from quote>",
  "address": {
    "full_name": "اسم المستلم",
    "phone": "+970599123456",
    "city": "خانيونس",
    "area": "الحي",
    "details": "وصف العنوان",
    "landmark": "علامة قريبة"
  }
}
```

`coupon_code`, `notes`, وإحداثيات `address.lat/lng` اختيارية. `payment_method` هو `cod` أو `jawwal_pay` التجريبي. يعاد الطلب نفسه عند إعادة الجسم نفسه والمفتاح نفسه للمستخدم نفسه؛ إعادة المفتاح بجسم مختلف تُرفض. تغير السعر/السلة/رسوم التوصيل/الكوبون أو انتهاء الحجز يستلزم مراجعة جديدة.

طلبات COD تبقى غير مدفوعة. سجل الطلبات يعيد نفس شكل تفاصيل الطلب العامة. التنقل في واجهة MVP0 يستخدم `order_number`.

## الكتالوج

تحديث الأسعار: كل خيار يحتوي `price` (سعر البيع المستخدم في السلة والطلب) و`compare_at_price` اختياري (السعر السابق). لا يُعرض السابق إلا إذا تجاوز سعر البيع. نسبة الخصم = `(السابق - الحالي) / السابق × 100`. لا يمثل `base_price` أو سعر حجم آخر سعرًا سابقًا. يُدخل السعر السابق من إدارة المنتج ← المتغيرات، وتلزم مهاجرة `2026_09_26_000000_add_variant_compare_at_price.php`. بيانات Seed لا تُمنح خصومات تلقائية.

`GET /products`: يدعم `category_id` مع الأبناء، البحث، `min_price/max_price` على أقل سعر نشط المعروض في البطاقة، و`sort=price_asc|price_desc|newest`؛ الواجهة تترجم أسماء الفرز تلقائيًا. الخيارات غير النشطة لا تُعرض.

## الدفع والأخطاء

- `POST /payments/init`: جلسة محاكاة فقط في `local/testing` مع Sandbox؛ ليست تكاملًا معتمدًا لدى مزود الدفع.
- webhook يتحقق من الحالة والمبلغ والمرجع، ولا يسمح للإشعار المكرر بإرجاع دفعة مكتملة إلى الفشل.
- خارج بيئة الاختبار، توقيع webhook مطلوب ولا يقبل سرًا فارغًا؛ الدفع الإنتاجي لم يُنفذ.
- `409`: تعارض مخزون/حجز/عرض/مفتاح. `422`: مدخلات غير صحيحة. الواجهة تحفظ محاولة الطلب غير المحسومة عند انقطاع الاتصال وتعيد نفس المفتاح.

الهيدرات المسموحة عبر CORS تشمل `X-Guest-UUID`, `Authorization`, `Idempotency-Key`, `Accept-Language`؛ أصل الواجهة من `FRONTEND_URL` في إعداد الخلفية.
