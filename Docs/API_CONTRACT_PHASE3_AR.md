# المرحلة 3 — الاكتشاف: عقد الـ API + برومت عاصم

الواجهة جاهزة وتعمل الآن على الموقع الحي في وضع العرض (`.env.production` ← `VITE_DEMO_FIXTURES=true`).
الأنواع المرجعية: `src/types/api.ts` (Brand · ProductBrief.brand · PaginationMeta.facets).

## برومت عاصم (جاهز للنسخ)

```
أنت تعمل على Backend مشروع Gazabella (Laravel 12 · Filament v3 · Sanctum). المرجع: Docs/openapi.yaml و GAZABELLA_PLAYBOOK.
الواجهة نُفّذت للمرحلة 3 (الاكتشاف) وتنتظر هذا العقد حرفياً. لكل بند: Migration + Resource + Filament + Feature Test،
وحدّث openapi.yaml. لا تعلن بنداً جاهزاً بدون مخرجات `php artisan test --compact`.
تنبيه D-STORE: «الماركة» = الشركة المصنّعة للمنتج (مثل L'Oréal) وليست المتجر المورّد. لا تخلطها بالمتاجر أبداً.

══════════════════════════════════════
P3-1 الماركات (المسارات موجودة جزئياً)
══════════════════════════════════════
ما تحققنا منه على Cloud: GET /brands و GET /brands/{slug} يعملان، وفلتر /products?brand_id= يعمل،
لكن كل المنتجات brand = null ← لذلك صفحات الماركات فارغة.
المطلوب:
1) ربط المنتجات بماركاتها في البيانات (Seeder/من لوحة الإدارة) — حقل «الماركة» إلزامي في نموذج المنتج في Filament
   (مع خيار «بدون ماركة» صريح).
2) على GET /brands و /brands/{slug}: إضافة description (nullable, مترجم) · cover_url (nullable) ·
   products_count (عدد المنتجات المتوفرة المنشورة). /brands يُرجع فقط الماركات التي لها منتج متوفر واحد على الأقل،
   مرتبة حسب sort_order ثم الاسم.
3) brand في ProductResource بالشكل: "brand": { "id": 1, "name": "جازابيلا", "slug": "gazabella" } (أو null) —
   في القوائم والتفاصيل.
4) Filament BrandResource: رفع شعار (PNG/WebP شفاف، ≥ 256×256)، الوصف، الغلاف، الترتيب، التفعيل.
5) إعدادات الرئيسية: أضف المفتاح "brands" إلى خيارات «أقسام الرئيسية» (بين deals و best_sellers)،
   فالقائمة المقبولة صارت: deals · brands · best_sellers · picks · promo · new · budget · reorder · recent · services.
اختبارات: brand_id يفلتر بدقة · /brands لا تُرجع ماركة بلا منتجات · brand في JSON المنتج.

══════════════════════════════════════
P3-2 عدادات الفلاتر (facets)
══════════════════════════════════════
على GET /products أضف داخل meta (للنتائج بعد تطبيق كل الفلاتر عدا الفلتر نفسه — المعيار المعتاد للـ facets):
"meta": { ...pagination,
  "facets": {
    "categories": [ { "slug": "skincare", "count": 12 } ],
    "brands":     [ { "slug": "gazabella", "count": 4 } ]
  }
}
- أي قيمة بعدد 0 تُحذف. الحساب باستعلام GROUP BY واحد لكل نوع + كاش 60 ثانية حسب مفتاح الفلاتر.
- «عرض المزيد» في الواجهة يعتمد على page/last_page الحالية — لا تغيير مطلوب.
اختبار: facets تتغير مع search و min_price، ولا تتأثر categories بفلتر category نفسه.

══════════════════════════════════════
P3-3 عمليات البحث الشائعة
══════════════════════════════════════
- جدول search_logs: term (lowercase, trimmed) · results_count · user_id (nullable) · created_at.
  يُسجَّل من GET /products?search= (بحث فعلي فقط، ≥ 2 حرف)، بدون IP أو بيانات شخصية.
- GET /search/popular?limit=8 → { "data": ["سيروم", "عطر", ...] }
  أكثر العبارات بحثاً خلال 30 يوماً التي لها نتائج (results_count > 0)، مع استبعاد قائمة كلمات ممنوعة يديرها المشرف.
  كاش ساعة.
- Filament: صفحة «عمليات البحث» — الأكثر بحثاً، و«بحث بلا نتائج» (مؤشر لمنتجات مطلوبة غير متوفرة)، وإدارة الكلمات الممنوعة،
  وإمكانية «تثبيت» عبارات تظهر أولاً.
حتى يجهز المسار: الواجهة تعرض أسماء الأقسام الحقيقية كاقتراحات.

══════════════════════════════════════
صيغة الرد المطلوبة
══════════════════════════════════════
جدول: [البند | ما تم | الدليل | الحالة ✅/🔧/❓] + مخرجات php artisan test --compact
+ JSON فعلي لـ GET /brands و GET /products?per_page=2 (مع facets) و GET /search/popular.
الأولوية: P3-1 (ربط المنتجات بالماركات أولاً) ← P3-2 ← P3-3
```

## ما يعمل الآن بدون باك اند
- «عرض المزيد» في الكتالوج.
- اقتراحات البحث من أسماء الأقسام.
- شريط الماركات وصفحاتها بالماركتين الحقيقيتين (+ ماركات توضيحية في وضع العرض فقط).
