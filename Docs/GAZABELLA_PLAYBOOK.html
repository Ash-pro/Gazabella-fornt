🧭 منهجية «البوابة والمسار» — Gate & Track

هذا الملف هو المرجع الوحيد للبرمجة والتصميم والتحليل والسيناريوهات. أي نص في ملف آخر يخالفه يُعتبر تاريخياً. العمل مقسّم إلى 4 مراحل، كل مرحلة وحدة مستقلة تُفتح ببوابة وتُغلق ببوابة، وداخلها 6 مسارات تعمل بالتوازي.

المسارات والمالكون

  • BE الباك اند ولوحات Filament — عاصم
  • FE واجهة العميل React — أشرف
  • UX التصميم، النصوص، مواصفات اللوحات — أشرف
  • QA الاختبارات والقبول — مشترك (كل طرف يختبر عمل الآخر)
  • OPS الاستضافة والتشغيل الميداني — عاصم تقنياً · أشرف ميدانياً
  • BIZ قرارات تجارية وقيم — صاحب المشروع

  • G-01 فجوة موثقة في الكود — لها حل مؤقت ونهائي
  • C-P1-02 عقد مشترك (API · حدث · إعداد)

دورة حياة البطاقة

  • لم تبدأ ← جاهزة (عقدها وتبعياتها جاهزة)
  • ← قيد التنفيذ ← بانتظار الدليل
  • ← مُغلقة بدليل · أو متعطلة مع سبب ومالك الحل
  • قاعدة: لا تتجاوز بطاقتان «قيد التنفيذ» لكل شخص في نفس الوقت

الإيقاع الأسبوعي (Asia/Gaza)

  • الأحد — تخطيط 20 دقيقة: اختيار بطاقات الأسبوع من المرحلة المفتوحة
  • الثلاثاء — مزامنة العقود 15 دقيقة: أي عقد تغيّر؟ أي بطاقة متعطلة؟
  • الخميس — يوم الدليل: عرض ما أُنجز على Staging، إغلاق البطاقات، تحديث هذا الملف
  • يومياً — رسالة واحدة: أمس · اليوم · عائق

قواعد البوابات

  • الحاجز: بطاقات المرحلة التالية لا تبدأ قبل إغلاق بوابة الخروج، باستثناء بطاقات UX وBIZ التمهيدية (تصميم وقرارات).
  • إعادة الفتح: خلل في مرحلة مغلقة ← بطاقة R- في المرحلة الحالية. البوابة القديمة لا تُعاد إلا إذا كُسر أحد معايير خروجها.
  • المؤقت ليس نهائياً: كل حل مؤقت له بطاقة نهائية مسجلة في مرحلة لاحقة — لا يُنسى.
  • الدليل: اسم الاختبار الناجح، أو لقطة شاشة من Staging، أو رابط PR. يُكتب في حقل evidence.

كيف أحدّث هذا الملف

  1. افتح الملف في المحرر وابحث عن const PLAN — كل المحتوى بيانات فقط.
  2. غيّر status للبطاقة (todo · ready · doing · review · done · blocked) وأضف evidence.
  3. عند إغلاق مرحلة: gate: 'closed' لها وgate: 'open' للتالية، وأضف سطراً في log.
  4. Commit برسالة: docs(playbook): P1-BE-02 → done. الملف يعيش في Git بجانب الكود.
  5. زر «📋 برومبت» على كل بطاقة BE/FE ينسخ برومبت جاهزاً لـ Codex / Claude / Cursor يتضمن السياق والقواعد وتعريف الإنجاز.

الهوية والخصوصية

  • لا store_id ولا commission_amount ولا sub_orders ولا اسم/شعار/SKU متجر في أي استجابة للعميل — HTTP وWebSocket والأخطاء والفواتير.
  • المتجر لا يرى اسم العميل ولا هاتفه ولا عنوانه ولا العمولة.
  • السائق يرى بيانات المستلم بعد shipped فقط، ولا يرى كود التسليم أبداً.
  • الصور بأسماء {uuid}.webp بلا EXIF.

المخزون والطلب

  • الإضافة للسلة لا تحجز. الحجز POST /cart/reserve 15 د + تمديد واحد بسقف 30 د.
  • Heartbeat للقراءة فقط.
  • order.status ≠ payment_status. بعد التحصيل/الدفع: confirmed.
  • POST /orders يتطلب Idempotency-Key.
  • المعرّف في الروابط order_number لا الرقم.

المعمارية

  • React لواجهة العميل فقط. الإدارة والمتجر والسائق Filament v3 داخل الباك اند.
  • لا REST API للوحات. لا /api/v1/store/* ولا /api/v1/delivery/*.
  • العزل عبر getEloquentQuery() + Policies — لا إخفاء أزرار.
  • التخزين sub_orders؛ «Vendor Order» مفهوم فقط.
  • Bearer Token فقط للـ API · 127.0.0.1 لا localhost.

الجودة والتوثيق

  • Docs/openapi.yaml مرجع العقد — لا يتغير إلا بعقد C-xx معتمد من أشرف.
  • لا تُعلن endpoint جاهزاً قبل Feature Test ناجح.
  • لا تُعلن رقم اختبارات لم يُشغَّل.
  • OTP test_mode محلياً فقط — ممنوع في الإنتاج.
  • لا كود يفترض استجابة مزود (Jawwal · SMS) قبل وثائقه الرسمية.
