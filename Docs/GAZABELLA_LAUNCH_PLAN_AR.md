## تعريف المشروع والهدف منه

### ما هو Gazabella؟

- متجر إلكتروني لمنتجات الجمال والعناية والعطور والهدايا، يقدم للعميلة تجربة عربية وإنجليزية تحت علامة واحدة.
- يتيح اكتشاف المنتجات والبحث والتصفية واختيار المنتج وإضافته للسلة وإتمام الطلب ومتابعته.
- خلف الواجهة نموذج **تجميعي**: الطلب الواحد قد يتوزع على أكثر من متجر شريك (حصص متاجر / `sub_orders`)، والعميلة لا ترى إلا علامة Gazabella.

### الهدف التجاري وتجربة العميلة

- تحويل التصفح إلى قرار شراء واضح: منتج مفهوم، سعر صحيح، توفر موثوق، وتوصيل معلوم.
- تقديم رحلة متصلة من البحث إلى الاستلام وما بعد البيع.
- تقليل الحاجة للتواصل اليدوي لمعرفة السعر والتوفر وحالة الطلب.
- بناء الثقة عبر دقة المعلومات، وأصالة المنتجات، وحفظ الحقوق، وإمكانية تتبع العمليات.

### هدف الإطلاق v1

متجر يبيع **بالدفع عند الاستلام فقط** داخل مناطق التوصيل المفعّلة، باللغتين، وتُدار كل عملياته (الطلبات، حصص المتاجر، التوصيل، التحصيل، الإلغاء والاسترجاع) **من لوحة Filament** بواسطة فريق التشغيل، دون أي تعديل يدوي على قاعدة البيانات. التفاصيل الكاملة للنطاق في القسم الثاني §1.

### البنية التقنية

- **الواجهة:** React وTypeScript وVite، مع React Router وTanStack Query وZustand ونظام ترجمة داخلي. النماذج: React Hook Form وZod. الأنماط: CSS وTailwind. الاستضافة على Vercel مع `middleware.ts` لمعاينات الروابط.
- **الاتصال:** REST API عبر Axios تحت `/api/v1`، مع تكامل مشروط الإعداد لـ Laravel Echo/Reverb.
- **الباك إند:** Laravel، نماذج وخدمات للمنتجات والسلة والحجز والطلبات وحصص المتاجر والكوبونات، ولوحة إدارة Filament.
- **البيئة الحالية:** Laravel Cloud (development): API تحت `/api/v1`، Swagger تحت `/api/documentation`، الإدارة تحت `/admin`. لا توجد بيئة Production منفصلة بعد.
- **ثلاثة أوضاع في الواجهة يجب التمييز بينها:** المحاكاة (mock)، العقد الافتراضي (legacy)، وعقد `mvp0`.

## 1. نطاق الإطلاق v1

### داخل الإطلاق v1

- تصفح وبحث وفلترة باللغتين، وصفحة منتج بمتغيرات صحيحة.
- سلة للزائرة ثم دخول برمز OTP حقيقي، ثم إتمام طلب COD بحجز وعرض إجمالي ومنع تكرار.
- خيار الهدية (رسالة + بيانات مستلم) وفق القرار L-04.
- صفحة طلباتي، تفاصيل الطلب، التتبع (تحديث دوري، واللحظي عند جاهزيته)، وإلغاء قبل الشحن.
- سياسات وتواصل ومناطق ورسوم من مصدر واحد يُدار من Filament.
- تشغيل كامل للطلب من Filament دون أي تعديل يدوي على قاعدة البيانات.
- إشعار الفريق بالطلب الجديد، وإشعار العميلة بالحالات الأساسية.

### خارج الإطلاق v1 (مخفي من الواجهة، وليس "قريباً")

- جوال باي وأي دفع إلكتروني (D-01 · D-17).
- المحفظة والرصيد.
- لوحات React للتاجر والسائق، وأي REST API للوحات (الإدارة والمتجر والسائق في Filament فقط).
- نظام تذاكر دعم داخلي (الدعم عبر واتساب في v1).
- أتمتة التسويات المالية (v1 = تقرير قابل للتصدير من بيانات snapshot صحيحة).
- برامج الولاء والإحالات وPartner API.

## 9. بوابة Go / No-Go

يُطلق المتجر للعامة فقط عند تحقق **كل** البنود:

1. [ ] كل مهام P0 (FE وBE وOPS) مغلقة بدليل.
2. [ ] سيناريوهات S-01 حتى S-17 ناجحة على **Production** بطلب حقيقي واحد على الأقل يُلغى بعدها.
3. [ ] OTP يصل لشبكتي جوال ووطنية.
4. [ ] الكتالوج بالعدد المتفق عليه (L-09) كامل البيانات باللغتين.
5. [ ] فحص التسريب نظيف على Production.
6. [ ] نسخة احتياطية حديثة وتجربة استعادة ناجحة موثقة.
7. [ ] Sentry يستقبل أخطاء الواجهة والخادم، وتنبيه الطابور يعمل.
8. [ ] الـ Pilot انتهى دون خلل مفتوح بدرجة حرجة أو عالية.
9. [ ] فريق التشغيل نفّذ 10 طلبات على الأقل حتى التسليم والتحصيل باستخدام SOP.
10. [ ] السياسات المنشورة مطابقة للتشغيل الفعلي (OPS-06).
11. [ ] خطة الرجوع جاهزة: الإصدار السابق للواجهة معروف، ونسخة القاعدة قبل النشر محفوظة.
12. [ ] أشرف وعاصم وقّعا تقرير القبول المرتبط بالإصدار.

**تصنيف الأخطاء في الـ Pilot:** حرج = يمنع البيع أو يسبب خطأ مالي/تسريب بيانات · عالٍ = يكسر رحلة أساسية وله حل يدوي مؤقت · متوسط/منخفض = لا يمنع الإطلاق ويُسجل في P1.

## 13. قواعد العمل المشتركة

- أي endpoint جديد أو حقل جديد يُضاف إلى `openapi.yaml` قبل التنفيذ، والإضافة فقط بلا إعادة تسمية.
- لا يُعلن endpoint جاهزاً قبل اختبار Feature ناجح.
- لا تُعرض في الواجهة قدرة غير موجودة في العقد المعتمد.
- عاصم يرسل عند إغلاق كل مهمة: اسم الاختبار أو `curl` مع الرد + رقم الـ commit.
- أشرف يرسل عند إغلاق كل مهمة: لقطة/فيديو السيناريو على Staging + رقم الـ commit.
- اجتماع متابعة قصير مرتين أسبوعياً على هذه الجداول فقط: ما أُغلق، ما يحجز، أي قرار جديد يُضاف إلى §3.
