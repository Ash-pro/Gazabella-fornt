أنت تعمل على Backend مشروع Gazabella (Laravel 12 · Filament v3 · Sanctum). المرجع: Docs/openapi.yaml و GAZABELLA_PLAYBOOK.
الواجهة (React) نُشرت وفيها أقسام جديدة للرئيسية تقرأ من GET /settings و GET /products. نفّذ البنود أدناه مع

قاعدة ثابتة D-STORE (أولوية قصوى)
══════════════════════════════════════
Gazabella تظهر للعميلة كمتجر واحد. التوريد من عدة متاجر داخلي فقط.
- ممنوع ظهور أي اسم متجر/مورد أو store_id أو sub_order أو commission في أي رد API عام أو للعميلة:
  /products · /products/{slug} · /products/{slug}/related · /cart · /checkout · /orders · /orders/{n} · /orders/track · /banners · /settings
- راجع نصوص المحتوى في قاعدة البيانات واحذف أي عبارة توحي بتعدد المتاجر، خصوصاً:
  · tagline و subtitle البانرات (مثل «من مصادر مختارة»، «متاجر متعددة»)
  · أوصاف المجموعات والأقسام والمنتجات
- شغّل: node scripts/leak-scan.mjs --base <API> --stores "<أسماء المتاجر الموردة مفصولة بفواصل>"
  وأرسل الناتج (يجب 0 مخالفات). أضف اختبار Feature يتأكد أن ProductResource و OrderResource للعميلة
  لا تحتوي المفاتيح: store, store_id, store_name, vendor, sub_orders, commission_rate_snapshot.

1) إعدادات الصفحة الرئيسية في Filament (N-07 + N-01)
══════════════════════════════════════
صفحة إعدادات جديدة في /admin باسم «الصفحة الرئيسية» (Settings page أو حقول داخل صفحة الإعدادات الحالية)
تُحفظ في جدول settings وتُرجع داخل GET /settings بهذا الشكل بالضبط:

  "sections": [
    { "key": "deals",        "enabled": true  },
    { "key": "best_sellers", "enabled": false },
    { "key": "picks",        "enabled": true  },
    { "key": "promo",        "enabled": true  },
    { "key": "new",          "enabled": true  },
    { "key": "budget",       "enabled": true  },
    { "key": "reorder",      "enabled": true  },
    { "key": "recent",       "enabled": true  },
    { "key": "services",     "enabled": true  }
  ],
  "trust": [
    { "icon": "truck",   "title": "توصيل خلال 45 دقيقة",  "text": "داخل خان يونس" },
    { "icon": "shield",  "title": "ادفعي بعد ما تفحصي",   "text": "نقداً للمندوب عند الاستلام" },

في Filament:
- «أقسام الرئيسية»: Repeater قابل لإعادة الترتيب بالسحب (->reorderable()) فيه:
  Select المفتاح (القيم التسع أعلاه فقط، بتسميات عربية: عروض اليوم · الأكثر طلباً · مختارات Gazabella ·
  بانر ترويجي · وصل حديثاً · حسب الميزانية · اطلبيها مرة أخرى · شاهدتِ مؤخراً · خدماتنا) + Toggle «ظاهر».
  ->distinct() لمنع تكرار المفتاح، والقيمة الافتراضية = القائمة أعلاه بالترتيب نفسه.
- «شريط الثقة»: Repeater بحد أقصى 4 عناصر: Select الأيقونة
  (truck · shield · refresh · dollar · clock · whatsapp · sparkle) + عنوان (≤ 30 حرفاً، مطلوب) + وصف (≤ 40 حرفاً، اختياري).
  الحقول مترجمة (ar/en) مثل باقي الإعدادات، والرد يرجع حسب ?lang=.
- إن تُرك «شريط الثقة» فارغاً: لا ترسل trust (أو أرسله null) — الواجهة تبني الشريط من مناطق التوصيل والسياسات.
- بعد الحفظ: امسح كاش /settings (الواجهة تخزنه 5 دقائق، والرد عليه Cache-Control max-age=60).
اختبار: GET /settings يعيد home.sections و home.trust بالشكل أعلاه، ومفتاح غير معروف لا يُقبل في الحفظ.

2) عروض اليوم — on_sale (N-02)
══════════════════════════════════════
- GET /products?on_sale=1 ← فقط المنتجات التي discount_price غير null وأقل من price، ومتوفرة (in_stock).
- اختياري: حقل sale_ends_at (datetime) على المنتج + إظهاره في ProductResource، وفي Filament حقل
  «ينتهي العرض في» داخل نموذج المنتج؛ عند انتهائه يُعامل المنتج كأنه بلا خصم (Scope أو Job كل ساعة).
- في Filament: عمود «عليه خصم» + فلتر في قائمة المنتجات لتسهيل إدارة العروض.
اختبار: منتج بخصم يظهر · منتج بلا خصم لا يظهر · خصم منتهٍ (sale_ends_at في الماضي) لا يظهر.

══════════════════════════════════════
3) الأكثر طلباً — sort=-sales_count (N-04)
══════════════════════════════════════
- عمود sales_count (unsigned int, default 0, index) على products.
- يزيد بكمية البند عند تأكيد الطلب (confirmed) ويُنقص عند الإلغاء/الاسترجاع — داخل نفس منطق
  OrderConfirmationService، وبشكل idempotent (لا يتكرر عند إعادة التأكيد).
- Command لإعادة الحساب من order_items للطلبات المؤكدة: php artisan products:recount-sales (يُشغَّل مرة الآن ويُجدول ليلياً).
- GET /products?sort=-sales_count مدعوم في الـ allowlist الخاص بالترتيب.
- sales_count لا يُرجع في الرد العام (رقم تجاري داخلي) — يُستخدم للترتيب فقط.
- في Filament: عمود «مرات الطلب» في قائمة المنتجات (للإدارة فقط).
- بعد التنفيذ والتأكد: فعّل القسم من «أقسام الرئيسية» (best_sellers ← ظاهر). الواجهة تخفيه افتراضياً.
اختبار: ترتيب صحيح · الإلغاء يُنقص · إعادة التأكيد لا تضاعف · الحقل غير موجود في JSON العام.
