# Gazabella Frontend

واجهة Gazabella المبنية بـ React 19 وTypeScript وVite وTailwind CSS. نطاق العمل الحالي: **MVP 0 المعتمد** في آخر تبويب من `Docs/Gazabella_artifact_v15.html`، ومهام أشرف للفرونت إند فقط.

## العرض التجريبي

لا يتطلب Mock Mode تشغيل Laravel. إعداد `.env` المطلوب:

```dotenv
VITE_DATA_SOURCE=mock
VITE_MOCK_DELAY_MS=250
```

```bash
npm install
npm run dev
```

افتح `http://127.0.0.1:5173`. يظهر شريط **⚡ وضع البيانات الوهمية (Mock Mode)** للتنقل بين المتجر ولوحة التاجر ولوحة التوصيل.

- تسجيل الدخول يقبل رقمًا فلسطينيًا بصيغة محلية أو دولية؛ رمز العرض هو `123456`. لا تُرسل رسائل SMS.
- اختيار المنتج والنوع والكمية، ثم السلة، فالعنوان وطريقة التوصيل، ثم المراجعة والدفع التجريبي.
- رمز الخصم التجريبي `GAZA2026` يخصم 20 شيكل بحد أقصى قيمة المنتجات.
- زر تأكيد الدفع يحاكي نجاح العملية فقط. لا يُخصم أي مبلغ ولا تنشأ شحنة حقيقية.
- بيانات السلة والطلبات والمخزون والتجهيز والبلاغات محفوظة محليًا في المتصفح. العرض يستخدم بيانات مشتركة لتسهيل تبديل الأدوار؛ ليس نظام صلاحيات حقيقيًا.
- يمكن إعادة بيانات العرض الافتراضية من «إعادة ضبط» في الشريط. يمسح ذلك تعديلات العرض المحلية؛ لا يمسح ملفات المشروع.

## التحقق

```bash
npm run lint
npm test
npm run build
```

اختبارات `tests/mock-flows.test.mjs` تعمل بذاكرة تخزين منفصلة؛ لا تغير بيانات المتصفح ولا تتصل بباك إند أو بوابة دفع.

## البنية

- `src/api/gazabella.ts`: واجهة اختيار مصدر البيانات وتكامل REST الحالي.
- `src/mock/mockServices.ts`: محاكاة خدمات البيانات.
- `src/mock/demoOperations.ts`: عمليات المخزون والتجهيز والتسليم والبلاغات التجريبية فقط.
- `src/lib/apiClient.ts`: Axios وترويسات Bearer/Guest ومعالجة الأخطاء.
- `src/hooks/useCartActions.ts`: توحيد تحديث السلة والانتقال إلى Checkout.
- `src/stores/checkoutStore.ts`: حفظ مسودة العنوان وجلسة الدفع والطلب الجاري في sessionStorage.
- `src/components/ui/Dialog.tsx`: نوافذ ودرج باستخدام dialog مع حصر التركيز وإعادته.
- `public/sw.js`: تخزين الأصول العامة فقط، دون استجابات API أو بيانات الطلبات.

## قواعد التدفق

- Heartbeat قراءة فقط كل خمس دقائق وعند استعادة الاتصال/ظهور الصفحة، ولا يمدد الحجز.
- Countdown مشتق من موعد الانتهاء، وليس عدادًا يتباطأ عند ترك علامة التبويب.
- التمديد في Checkout مرة واحدة لكل حجز، بمقدار 15 دقيقة في العرض التجريبي.
- تعديل السلة يبطل جلسة المراجعة السابقة حتى لا تُعرض مبالغ قديمة.
- يُحفظ معرّف الطلب قبل بدء الدفع؛ إعادة محاولة الدفع تستخدم الطلب نفسه.
- نجاح الدفع لا يُستنتج من رابط العودة. تعرض الصفحة حالة الطلب المسترجعة من مصدر البيانات.
- روابط تفاصيل الطلب تستخدم `order_number`.
- لا تحتوي بيانات منتجات العميل على معرف المتجر أو العمولة أو vendor_orders.
- المحفوظات محلية وتصفّي المنتجات الموجودة في صفحة النتائج المعروضة.

## الربط الحقيقي لاحقًا

راجع `Docs/FRONTEND_MVP0_HANDOFF.md` قبل تبديل المصدر إلى `api`. التبديل وحده لا يعني اكتمال تكامل Store/Delivery أو الدفع أو النزاعات. لا توجد عودة تلقائية للبيانات الوهمية عند فشل API. لم يُعدّل الباك إند أو عقد OpenAPI.

الصور المستخدمة في الواجهات بصيغة WebP. احتُفظ بصور JPG الأصلية في مجلد الأصول للرجوع إليها.
